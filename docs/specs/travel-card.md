# 여행 대표 카드 개발 명세

작성일: 2026-11-14

대상: 마실 모바일 앱의 여행 기록 카드 생성·편집·공유

상태: 개발 기준 명세. 제품 방향은 대화에서 정한 내용을 반영하고, 추가 기술 선택은 아래의 구현 기본안으로 구분한다.

## Problem Statement

여행을 마친 사용자는 자신이 어디에 다녀왔고 어떤 순간을 남겼는지 사진으로 간단히 보여주고 싶다. 사진을 고르고, 여러 장을 배치하고, 제목을 붙이는 작업을 다른 편집 앱에서 반복하는 것은 번거롭다. 마실에 이미 여행 일정과 인증 사진이 있어도 이를 공유하기 좋은 한 장으로 만드는 과정은 충분히 제공되지 않는다.

현재 기능은 DAY별 방문 기록을 PNG 카드로 만드는 방식이다. 날짜 중심의 기본 제목, 인증 사진 중심의 입력, 고정된 사진 자르기 방식 때문에 여행의 분위기를 사용자가 직접 정리하기 어렵다. 사용자는 이 기능을 PDF 포토북으로 인식하고 있었지만, 확인한 현재 출력 형식은 PNG다.

개선의 중심은 긴 포토북 편집보다 **“내 여행을 보여주는 카드를 간단히 완성해서 공유하기”**다. 공유 의도가 실제로 더 큰 사용 동기인지는 제품 가설이며, 현재 앱 사용자 조사로 확인된 사실로 취급하지 않는다.

## Solution

다녀온 루트에서 **여행 전체를 대표하는 카드 한 장**을 기본으로 만든다. 기존 인증 사진을 자동으로 채우고, 사용자는 사진과 제목을 확인한 뒤 필요한 부분만 수정해 저장하거나 시스템 공유 화면으로 보낸다.

기본 흐름은 다음과 같다.

1. **다녀온 루트 목록 → 카드 만들기**: DAY 상세를 먼저 찾지 않고 해당 여행에서 시작한다.
2. **자동 초안 확인**: 대표 사진 한 장, 보조 사진 최대 세 장, 기본 제목과 여행 정보를 배치한다.
3. **필요한 부분만 편집**: 사진 선택·교체·순서·잘리는 위치, 제목, 선택 사항인 짧은 한 줄을 수정한다.
4. **최종 카드 확인 → 저장 또는 공유**: 화면에서 확인한 편집 결과를 PNG로 전달한다.

| 요소 | 요구사항 |
| --- | --- |
| 결과물 | 여행 전체를 대표하는 카드 한 장이 기본이다. |
| 사진 | 대표 사진 한 장을 크게, 보조 사진 두세 장을 작게 배치하는 구성이 기준이다. 사진이 한두 장이어도 그 수에 맞게 배치한다. |
| 제목 | “강릉에서 보낸 이틀”처럼 여행을 드러내며, 사용자가 수정할 수 있다. 근거 없는 지역이나 기간을 자동으로 만들지 않는다. |
| 여행 정보 | 여행지와 날짜를 짧게 보여준다. 방문하지 않은 장소를 다녀온 곳처럼 표시하지 않는다. |
| 한 줄 | 사용자가 원할 때만 짧은 문장을 넣는다. 입력하지 않으면 해당 공간을 자연스럽게 정리한다. |
| 브랜드 | 마실 표시는 하단에 작게 배치한다. 사진과 제목이 먼저 보이게 한다. |
| 편집 | 배치는 자동으로 정하고, 사용자는 내용과 사진의 보이는 위치만 조정한다. |

기존 DAY별 카드의 제거는 이번 요구사항에 포함하지 않는다. 새 대표 카드가 기본 진입 결과가 되며, 기존 DAY별 기록은 호환성을 유지한다.

## User Stories

1. 여행을 마친 사용자로서, 다녀온 루트 목록에서 바로 카드를 만들고 싶다. DAY 상세를 여러 번 열지 않고 여행을 공유하기 위해서다.
2. 여러 날 여행한 사용자로서, 여행 전체를 대표하는 카드 한 장을 먼저 보고 싶다. 여러 DAY의 결과물을 직접 합치지 않고 여행을 보여주기 위해서다.
3. 인증 사진을 남긴 사용자로서, 사용할 수 있는 사진이 초안에 자동으로 채워지기를 원한다. 빈 화면부터 편집을 시작하지 않기 위해서다.
4. 사용자는 실제로 방문한 장소의 기록을 바탕으로 초안이 만들어지기를 원한다. 건너뛴 장소를 방문한 것처럼 보여주지 않기 위해서다.
5. 사진이 많은 사용자로서, 자동 선택된 사진을 다른 인증 사진으로 바꾸고 싶다. 여행을 가장 잘 보여주는 순간을 고르기 위해서다.
6. 사용자로서, 앨범에서 사진을 골라 카드에 추가하거나 교체하고 싶다. 방문 인증에 쓰지 않은 여행 사진도 활용하기 위해서다.
7. 사용자로서, 앨범에서 고른 사진이 카드 편집에만 사용되기를 원한다. 방문 인증 사진이나 공개 동의가 바뀌지 않게 하기 위해서다.
8. 사용자로서, 어떤 사진을 대표 사진으로 쓸지 선택하고 싶다. 가장 보여주고 싶은 사진을 크게 배치하기 위해서다.
9. 사용자로서, 카드 사진의 순서를 바꾸고 싶다. 원하는 흐름으로 여행을 보여주기 위해서다.
10. 사용자로서, 카드 사진 순서를 바꿔도 실제 루트의 장소 순서가 유지되기를 원한다. 기록 편집과 일정 변경이 섞이지 않게 하기 위해서다.
11. 사진이 한 장뿐인 사용자로서, 한 장에 맞는 완성된 배치를 보고 싶다. 빈 사진 칸이 남지 않게 하기 위해서다.
12. 사진이 두세 장인 사용자로서, 선택한 수에 맞는 자동 배치를 원한다. 정해진 장수를 억지로 채우지 않기 위해서다.
13. 사진을 선택한 사용자로서, 사진의 잘리는 위치를 조정하고 싶다. 사람이나 풍경의 중요한 부분을 카드에 남기기 위해서다.
14. 사용자로서, 사진을 교체하거나 순서를 바꾼 뒤에도 최종 배치를 확인하고 싶다. 대표·보조 영역의 모양이 달라졌을 때 다시 조정하기 위해서다.
15. 사용자로서, 원본 사진의 방향과 비율이 올바르게 반영되기를 원한다. 사진이 돌아가거나 늘어나지 않게 하기 위해서다.
16. 사용자로서, 날짜 중심의 기본 제목을 여행에 어울리는 제목으로 바꾸고 싶다. 어떤 여행이었는지 한눈에 전하기 위해서다.
17. 사용자로서, 필요하면 짧은 한 줄을 추가하고 싶다. 긴 여행기를 작성하지 않고도 개인적인 느낌을 남기기 위해서다.
18. 사용자로서, 한 줄을 작성하지 않아도 완성된 카드를 얻고 싶다. 추가 글쓰기가 공유의 필수 단계가 되지 않게 하기 위해서다.
19. 사용자로서, 여행지와 날짜를 간결하게 확인하고 싶다. 사진과 함께 여행의 맥락을 전하기 위해서다.
20. 사용자로서, 제목과 한 줄이 어색하게 두 줄로 끊기거나 잘리지 않기를 원한다. 공유한 이미지에서도 의도한 문장이 읽히게 하기 위해서다.
21. 사용자로서, 미리보기와 저장·공유한 이미지에 같은 내용과 사진 위치가 나오기를 원한다. 내보낸 뒤 결과가 달라지는 일을 피하기 위해서다.
22. 인증 사진이 없는 사용자로서, 앨범 사진을 선택하는 안내를 받고 싶다. 사진이 없다는 이유만으로 편집 방법을 찾지 못하지 않기 위해서다.
23. 사진을 불러오지 못한 사용자로서, 실패한 사진을 다시 불러오거나 교체할 수 있기를 원한다. 다른 편집 내용을 잃지 않고 완성하기 위해서다.
24. 사진 권한을 허용하지 않은 사용자로서, 선택을 취소하거나 기존 인증 사진으로 계속 작업하고 싶다. 권한 선택이 카드 편집 전체를 막지 않게 하기 위해서다.
25. 사용자로서, 사진 선택을 취소하면 기존 편집 내용이 유지되기를 원한다. 취소만으로 대표 사진이 사라지지 않게 하기 위해서다.
26. 사용자로서, 이미지를 준비하는 동안 진행 상태를 알고 싶다. 버튼을 반복해서 누르거나 앱이 멈췄다고 생각하지 않기 위해서다.
27. 사용자로서, 편집을 빠르게 연속 변경해도 마지막 선택이 결과에 반영되기를 원한다. 늦게 끝난 이전 생성 작업이 최신 결과를 덮어쓰지 않게 하기 위해서다.
28. 사용자로서, 다른 여행의 카드를 열면 해당 여행의 내용만 보고 싶다. 이전 여행의 사진이나 제목이 섞이지 않게 하기 위해서다.
29. 사용자로서, 완성한 이미지를 기기에 저장하는 동작을 시작하고 싶다. 나중에 다시 보거나 원하는 앱에서 사용하기 위해서다.
30. 사용자로서, 완성한 카드를 시스템 공유 화면으로 보내고 싶다. 설치된 앱 중 원하는 곳을 직접 선택하기 위해서다.
31. 사용자로서, 공유 화면을 닫아도 카드 편집 내용을 유지하고 싶다. 공유를 취소한 뒤에도 사진이나 제목을 다시 손보기 위해서다.
32. 사용자로서, 저장이나 공유가 실패하면 현재 카드로 다시 시도하고 싶다. 사진 선택부터 작업을 반복하지 않기 위해서다.
33. 웹에서 사용하는 사용자로서, 파일 공유를 지원하지 않는 환경에서는 다운로드로 결과를 받고 싶다. 브라우저 기능 차이 때문에 결과물을 잃지 않기 위해서다.
34. 사용자로서, 공유를 누르기 전에는 사진이 외부 서비스에 게시되지 않기를 원한다. 카드에 담긴 정보를 직접 확인하고 전달 대상을 고르기 위해서다.
35. 한국어 또는 영어를 사용하는 사용자로서, 기존 앱 언어에 맞는 안내와 날짜 표현을 보고 싶다. 편집과 공유 과정을 이해하기 위해서다.
36. 보조 기능을 사용하는 사용자로서, 선택된 대표 사진·순서·버튼 상태를 알 수 있기를 원한다. 드래그 동작에만 의존하지 않고 카드를 완성하기 위해서다.
37. 기존 DAY별 카드를 이용하는 사용자로서, 이전 기록 카드 기능을 계속 사용할 수 있기를 원한다. 대표 카드 추가로 기존 기능을 잃지 않기 위해서다.
38. 사용자로서, 카드 편집을 마치거나 닫아도 방문 상태·GPS 인증·공개 범위가 유지되기를 원한다. 이미지 편집이 여행 기록 자체를 바꾸지 않게 하기 위해서다.

## Implementation Decisions

### 1. 대화에서 정한 제품 범위

- 공유를 위한 여행 대표 카드가 우선이다. 긴 보관용 포토북은 후속 과제로 둔다.
- 기본 결과물은 여행별 한 장이다. 모든 방문 장소와 모든 사진을 한 장에 나열한다는 뜻은 아니다.
- 대표 사진 한 장과 보조 사진 최대 세 장을 사용한다. 네 장보다 적으면 사진 수에 맞게 자동 배치한다.
- 인증 사진으로 초안을 채우되, 사용자는 앨범 사진으로 바꿀 수 있다.
- 편집 범위는 사진 선택·교체·순서·잘리는 위치·제목·선택적인 짧은 한 줄이다.
- 사진이 중심이 되도록 여행 정보는 짧게, 마실 표시는 작게 배치한다.

이하의 세부 동작은 위 범위를 기존 기능에 연결하기 위한 **구현 기본안**이다. 이전 대화에서 모든 세부값이 별도로 확정됐다는 의미는 아니다.

### 2. 진입점과 생성 대상

- 소유자의 다녀온 루트 목록에서 해당 루트의 `카드 만들기`로 시작한다. 다른 사용자의 공유 루트를 자신의 카드로 편집하는 흐름은 추가하지 않는다.
- 기존 생성 가능 판정을 재사용한다. 장소가 모두 `VISITED` 또는 `SKIPPED`로 정리된 DAY 중 실제 방문이 한 곳 이상 있는 DAY를 대상으로 한다. 이런 DAY가 하나 이상인 루트에서 생성할 수 있다.
- 대표 카드의 기본 인증 사진 후보는 위 대상 DAY들을 DAY 순서·장소 순서로 합친 실제 방문 기록이다. 미완료 DAY까지 생성 대상을 넓히는 규칙 변경은 하지 않는다.
- 전부 건너뛴 DAY는 자동 사진이나 방문 사실의 근거가 되지 않는다. 모든 DAY가 이 상태라면 앨범 사진만으로 방문 카드를 새로 만드는 예외도 추가하지 않는다.
- 기존 DAY 상세의 카드 진입과 출력은 보존한다. 새 목록 진입에서는 여행 대표 카드가 먼저 보인다.

### 3. 사진 선택과 자동 배치

- 초안에는 불러올 수 있는 인증 사진을 기존 기록 순서대로 최대 네 장 선택한다. 첫 사진을 대표로 두고 같은 인증 사진을 중복 자동 선택하지 않는다. 의미를 분석하는 사진 추천은 하지 않는다.
- 사용자가 사진의 순서를 바꾸면 첫 사진이 대표가 된다. 사진을 제거하면 남은 순서에 맞춰 대표·보조 역할을 다시 정한다.
- 한 장이면 대표 사진만, 두 장 이상이면 대표 사진과 보조 사진을 자동 배치한다. 사용하지 않는 사진 칸과 가짜 사진은 만들지 않는다.
- 사진 목록의 순서는 카드 안에서만 의미가 있다. 루트의 장소 순서·DAY 구성·방문 시각은 변경하지 않는다.
- 사진이 없으면 앨범에서 선택하도록 안내한다. 새 사진 중심 대표 카드의 내보내기는 사진 한 장 이상이 준비된 뒤 가능하다. 기존 사진 없는 DAY 기록 카드의 동작은 유지한다.
- 일부 인증 사진 로딩에 실패하면 사용 가능한 사진으로 편집을 계속하고 실패 사실과 재시도·교체 방법을 알린다. 실패한 사진을 정상적으로 포함했다고 표시하지 않는다.

### 4. 앨범 선택과 사진 정보의 경계

- 앨범 선택은 카드 사진을 추가·교체할 때만 시작한다. 권한 거절·선택 취소·읽기 실패는 기존 편집 내용을 지우지 않는다.
- 카드 사진은 기존 인증 사진 또는 로컬 앨범 사진을 가리키는 구분된 입력으로 처리한다. 앨범 사진을 선택했다고 방문 인증 저장 API를 호출하지 않는다.
- 앨범 사진에 장소·GPS 방문 사실을 자동으로 부여하지 않는다. 기존 사진 공개 동의, 루트 공개 여부, 방문 상태도 변경하지 않는다.
- 카드용 앨범 사진을 서버에 영구 업로드하거나 다른 사용자에게 노출하는 API는 추가하지 않는다. 기존 사진 선택 브리지에서 재사용할 수 있는 기능만 활용하고, 인증 저장 절차와는 분리한다.
- 원본을 덮어쓰지 않는다. 방향을 바로 반영한 이미지에서 카드용 미리보기·출력 이미지만 만든다.

### 5. 크롭과 사진 역할 변경

- 각 사진은 원본 비율을 유지하면서 배정된 영역을 채운다. 늘이거나 필터를 자동 적용하지 않는다.
- 사용자는 사진 안에서 보이는 중심 위치를 조정하고 기본 위치로 되돌릴 수 있다. 자유로운 프레임 크기 변경이나 임의 배치는 제공하지 않는다.
- 위치는 사진별 원본 기준의 정규화된 초점 좌표로 보관한다. 대표·보조 역할이나 미리보기 크기가 달라져도 같은 기준으로 최종 이미지를 자른다.
- 사진을 교체하면 새 사진의 기본 위치를 사용한다. 같은 사진의 순서를 바꾸면 해당 사진의 초점 위치는 유지하고 새 프레임에 적용한다.
- 터치 이동 외에 보조 기능으로 조작할 수 있는 위치 조정·초기화 방법을 제공한다.

### 6. 제목·한 줄·여행 정보

- 제목은 필수이며 직접 수정할 수 있다. 기본 제목은 신뢰할 수 있는 여행지·기간 정보가 있을 때만 이를 활용한다. 정보가 없으면 `나의 여행 기록`처럼 사실을 추측하지 않는 제목을 사용한다.
- “강릉에서 보낸 이틀”은 제목의 방향을 보여주는 예시다. 데이터 근거 없이 지역·박수·방문 완료 사실을 생성하지 않는다.
- 짧은 한 줄은 선택 입력이다. 비워두면 빈 레이블이나 불필요한 여백을 남기지 않는다.
- 제목과 한 줄은 카드에서 각각 한 줄로 표현한다. 실제 출력 글꼴과 가용 너비를 기준으로 검사하고, 들어가지 않으면 입력 단계에서 줄이도록 안내한다. 내보내기 시점에만 몰래 자르거나 두 줄로 바꾸지 않는다.
- 제목이 공백뿐이거나 문장이 출력 영역을 넘으면 수정 방법을 안내하고 내보내기를 막는다. 편집 자체는 계속할 수 있다.
- 날짜는 기존 루트의 날짜를 사용한다. 실제 방문 시각과 예정 날짜를 임의로 같은 의미로 바꾸지 않는다. 여행지의 신뢰할 수 있는 표시값이 없으면 생략한다.
- 사용자가 작성한 제목과 한 줄을 언어 변경 시 자동 번역하거나 덮어쓰지 않는다. 안내와 기본 문구·날짜 표현에는 기존 한국어·영어 지원을 적용한다.
- 사용자 입력은 텍스트로 안전하게 렌더링한다. 이미지 생성 과정에서 마크업으로 해석하지 않는다.

### 7. 시각적 구성과 편집 화면

- 정보의 우선순위는 사진 → 제목 → 여행 정보·한 줄 → 작은 마실 표시다. 큰 방문 수·사진 수 통계나 긴 장소 목록을 대표 카드의 주인공으로 두지 않는다.
- 마실의 기존 색상과 글꼴 체계를 따른다. 대표 카드에는 우선 하나의 자동 배치를 제공하며, 테마 선택을 시작 조건으로 요구하지 않는다.
- 사진 선택·순서 변경·위치 조정은 해당 사진과 연결해 제공한다. 작은 화면에서 편집 제어가 카드 확인이나 저장·공유 버튼을 가리지 않게 한다.
- 한국어 안내는 기존 앱의 해요체와 `해 주세요`를 사용한다. 짧은 버튼은 한 줄을 유지한다.
- 기존 DAY 카드의 테마·배경을 이번 작업에서 모두 다시 디자인하지 않는다. 새 대표 카드에 기존 다섯 테마를 일괄 확장하는 것도 요구하지 않는다.

### 8. 출력 계약

- 첫 버전은 기존 이미지 저장·공유 기반과 맞춰 **1080 × 1350, 4:5 비율, PNG, `image/png`**를 기본 출력으로 유지한다. PDF라는 이름으로 안내하지 않는다.
- 대표 카드는 사진 수와 DAY 수에 관계없이 한 장을 반환한다. 기존 DAY별 다중 카드 출력 계약은 유지한다.
- 생성 입력은 루트의 읽기 전용 정보, 선택 사진과 순서·초점 위치, 제목·한 줄을 포함한다. 편집 화면의 임시 상태나 DOM 크기에 의존해 결과가 달라지지 않게 한다.
- 출력은 저장·공유에서 공통으로 사용할 이미지와 파일 정보를 제공한다. 기존 DAY 결과와 구분할 수 있어야 하며, 기존 호출부에 새 편집값을 필수로 요구하지 않는다.
- 미리보기와 최종 생성은 같은 배치·크롭·텍스트 규칙을 사용한다. 내보내는 이미지는 현재 편집본과 일치해야 한다.
- 최초 대표 카드 표시를 위해 모든 DAY의 모든 이미지를 먼저 생성하지 않는다. 필요한 대표 카드와 선택 사진만 준비한다.

### 9. 상태 소유권과 비동기 처리

- 카드 편집 세션 한 곳이 제목·한 줄·선택 사진·초점 위치를 소유한다. 서버 루트 상태나 여러 하위 컴포넌트에 편집 상태를 복제하지 않는다.
- 루트 조회·인증 사진 후보는 기존 조회 결과에서 읽는다. 새 서버 스키마나 GraphQL 변경은 기본적으로 필요하지 않다.
- 이미지 생성·선택 작업은 자신이 속한 편집 세션과 최신 편집본을 식별한다. 이전 편집본이나 닫힌 세션의 완료 콜백이 현재 카드에 반영되지 않게 한다.
- 이미지 준비 중 상태를 표시하고 중복 저장·공유를 막는다. 오래된 이미지가 최신 편집 결과인 것처럼 내보내지지 않게 한다.
- 내보내기 실패와 공유 화면 취소는 편집본을 유지한다. 닫았다가 다시 열거나 계정을 바꿨을 때 이전 세션의 사진·제목이 다른 여행·사용자에게 남지 않게 한다.
- 새로 가져온 로컬 이미지의 임시 리소스는 세션 종료 시 정리한다. 여러 DAY의 큰 PNG를 동시에 보관하는 구조를 새 대표 카드에 반복하지 않는다.
- 앱 종료 후 초안 복구·기기 간 동기화·카드 서버 보관은 추가하지 않는다. 현재 세션의 실패 복구와 영구 초안 저장을 구분한다.

### 10. 저장·공유의 플랫폼별 동작

- 기존 이미지 저장·공유 경로를 우선 재사용한다. iOS의 현재 저장 동작은 시스템 저장·공유 화면을 열 수 있으므로, 버튼을 누른 즉시 사진 앨범에 저장됐다고 안내하지 않는다.
- 공유는 사용자가 명시적으로 누를 때 시스템 공유 화면에 파일을 전달하는 방식이다. 특정 SNS에 자동으로 게시하지 않는다.
- 시스템이 알려주는 성공·취소·실패 범위까지만 결과를 안내한다. 공유 화면을 열었다는 사실을 SNS 게시 완료로 취급하지 않는다.
- 공유 취소 후에는 현재 편집 화면으로 돌아와 계속 수정할 수 있다.
- 지원되는 웹 환경에서는 파일 공유를 사용하고, 지원하지 않으면 기존 다운로드 대체 경로를 유지한다.
- 현재 지원이 확인되지 않은 플랫폼의 앨범 직접 저장을 새로 보장하지 않는다. Android 전용 신규 저장 구현은 이번 범위에 포함하지 않는다.

## Testing Decisions

### 검증 경계

- **주 자동화 경계는 카드 생성 진입점의 외부 동작**이다. 루트 기록과 편집 입력을 주고 실제 이미지 결과·출력 정보를 확인한다. 내부 Hook 개수, 하위 함수 호출 순서, 컴포넌트 파일 분리 형태를 검증 대상으로 삼지 않는다.
- 기존 카드 렌더링 브라우저 픽스처와 DAY 카드 테스트를 선례로 사용한다. 새 대표 카드 시나리오는 실제 PNG 생성 경계에 추가하고, 새 모듈마다 구현을 그대로 따라가는 테스트를 만들지 않는다.
- PNG 생성만으로 확인할 수 없는 **사진 선택·네이티브 저장·공유**는 별도의 외부 플랫폼 경계로 확인한다. 브라우저 픽스처 결과만으로 iOS 전체 흐름이 검증됐다고 보고하지 않는다.
- 편집 중 연속 변경·닫기·다른 루트 열기는 기존 비동기 제어 테스트 방식과 실제 편집 화면에서 확인한다. 모든 하위 Hook을 개별 테스트하기보다 사용자의 최종 결과를 확인한다.
- 위 검증 범위를 포함한 명세에 대해 사용자가 `implement`로 구현을 요청했다. 새 테스트를 추가할 때도 카드 생성 결과와 사진 선택·저장·공유의 외부 경계를 유지한다.

| 화면·접근성 | 모바일 390 × 844, 웹 대체 화면, 큰 글씨·스크린리더·동작 줄이기 | 핵심 버튼이 가려지지 않는다. 사진 선택 상태와 순서를 알 수 있고 드래그 외 조작이 가능하다. 불필요한 움직임을 강제하지 않는다. |

레이아웃 자동 검증에는 합성 사진을 사용한다. 실제 크롭과 가독성 확인에는 테스트용 사용 허가 사진을 추가하며, 합성 단색 이미지 확인만으로 사진의 시각적 품질까지 통과했다고 판단하지 않는다. iOS 검증은 테스트 계정과 테스트 사진으로 사진 선택부터 편집·저장·공유·취소까지 이어서 수행한다.

구현 변경 범위의 타입 검사와 lint, 관련 기존 테스트를 실행한다. 네이티브 브리지가 바뀌면 해당 브리지와 WebView 번들 검증을 추가한다. 서버 계약을 바꾸지 않는 구현에서는 불필요한 API 전체 테스트나 데이터베이스 마이그레이션을 작업 조건으로 추가하지 않는다.

## Out of Scope

- 다중 페이지 PDF, 인쇄용 포토북, 제본·주문·결제.
- 자유 배치 캔버스, 프레임 크기 직접 변경, 스티커, 필터, 글꼴·색상 편집기.
- AI 사진 평가·자동 감성 문구·방문 사실 추정.
- 세로 9:16 등 여러 출력 비율과 일괄 내보내기.
- SNS 자동 게시, 공개 카드 피드, 팔로우·좋아요 기능.
- 카드용 사진의 서버 영구 저장, 카드 링크 발행, 기기 간 편집 동기화, 앱 종료 후 초안 복구.
- 전체 오프라인 지원을 위한 사진 선다운로드·전용 캐시. 이미 접근 가능한 로컬 이미지 활용과 완전한 오프라인 보장은 구분한다.
- 카드 편집으로 방문 인증 사진·GPS·방문 상태·루트 순서·공개 동의를 수정하는 기능.
- 미완료 DAY의 생성 자격 확대, 다른 사용자의 여행을 편집하는 기능.
- 기존 DAY 카드 삭제, 기존 다섯 테마 전체 재설계, Android 전용 신규 저장 기능.
- 공유 성과나 이용자 심리에 대한 검증되지 않은 수치 목표.

## Further Notes

- 완료 기준은 대상 루트에서 대표 카드 초안을 열고, 인증·앨범 사진 선택과 위치·제목·한 줄 편집을 거쳐, 같은 결과물을 저장·공유할 수 있으며 기존 여행 기록과 DAY 카드가 유지되는 것이다.
- 먼저 구현할 범위는 위 대표 카드 흐름이다. 테마나 출력 형식을 늘리는 일은 이 흐름을 쉽게 완성할 수 있는지 확인한 뒤 판단한다.
- 대표 카드의 정확한 사진 영역 비율·간격·글자 크기는 사진 한 장부터 네 장까지의 실제 시각 검증으로 정한다. 이 명세의 정보 우선순위·한 줄 규칙·편집 범위·출력 크기를 바꾸는 근거로 삼지 않는다.
- 이 문서는 요구사항과 구현 시의 검증 계획이다. 새 기능을 구현하거나 위 테스트를 실행해 통과한 결과 보고서가 아니다.
- 이슈 트래커와 분류 라벨의 프로젝트 설정이 확인되지 않았다. 저장소 원격 주소만으로 발행 위치를 확정하거나 새로운 분류 체계를 만들지 않는다. `to-spec` 지침에 따라 `/setup-matt-pocock-skills`로 설정한 뒤 이 명세를 `ready-for-agent` 라벨로 발행한다.
